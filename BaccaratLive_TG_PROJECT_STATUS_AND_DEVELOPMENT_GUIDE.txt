============================================================
1. 문서 목적
============================================================

현재까지 구현·검증된 상태를 기록하고, 앞으로는 개발용 Mock/Skeleton을
계속 확장하는 방식이 아니라 실제 서비스에 필요한 기능을 하나씩
Production 수준으로 완성하기 위한 기준 문서입니다.

개발 원칙:
- 기존 소스코드를 먼저 확인하고 이미 구현된 기능은 중복 작성하지 않습니다.
- Mock 기능은 최종 기능으로 간주하지 않습니다.
- 실제 인증 → 실제 DB → 실제 잔액 → 실제 게임 상태 → 실제 베팅 → 실제 정산 순서로 진행합니다.
- 한 단계의 구현과 테스트가 끝난 뒤 다음 단계로 이동합니다.
- 보안, 권한, 오류 처리, 중복 요청 방지도 각 기능과 함께 검토합니다.

7. 반드시 유지할 핵심 원칙
============================================================

1. Client는 게임 결과를 결정하지 않습니다.
2. Server가 게임 상태의 최종 권한을 가집니다.
3. 잔액은 Server에서만 최종 변경합니다.
4. 금액 계산에서 부동소수점 오류를 피합니다.
5. micro-USDT 단위를 일관되게 사용합니다.
6. 베팅과 잔액 변경은 Transaction 기준입니다.
7. 정산은 멱등성을 보장합니다.
8. 동일 거래의 중복 처리를 방지합니다.
9. Secret/Token/Private Key를 GitHub에 올리지 않습니다.
10. 개발용 bypass를 Production 인증으로 사용하지 않습니다.
11. Mock과 실제 데이터를 명확히 구분합니다.
12. 기능 하나를 실제 테스트까지 완료한 뒤 다음 기능으로 이동합니다.
